# Architecture & Storage Strategy

TheAndb follows a decoupled, modular approach using a polyrepo-like workspace.

## 📦 Package Structure

1. **`@the-andb/core` (The Brain)**:
   - Stateless library handling database connections, SQL parsing, dependency graph creation, and schema comparison/strategy generation.
2. **`@the-andb/cli` (The Tool)**:
   - Command-line interface wrapped around the core for integration into CI/CD pipelines. Uses `FileStorage` to manipulate `.sql` scripts.
3. **`andb-desktop` (The Face)**:
   - A premium Electron + Vue 3 desktop GUI with a unified `UniversalDataGrid` for browsing schemas, tables, and executing queries.
4. **`andb-mcp`**:
   - Model Context Protocol server exposing database access and schemas to AI tools.

---

## 💾 Storage Layer (Pluggable)

Storage backends are selected via the `Container` configuration to match execution modes:

### 1. FileStorage
- **Source of truth**: System folders containing `.sql` files.
- **Used by**: CLI, CI/CD pipeline.

### 2. SQLiteStorage
- **Source of truth**: A local SQLite database (`andb-storage.db` or `andb.db`).
- **Used by**: Desktop UI for instantly querying/filtering thousands of schema objects.

### 3. HybridStorage
- **Source of truth**: Writes to SQLite instantly for UI performance and pushes/syncs updates to SQL files on disk for Git version control.

## 🗄️ SQLite Internal Schema

### Table: `ddl_exports`
Indexes exported SQL statements for environments.

| Column | Type | Description |
|---|---|---|
| `environment` | `TEXT` | `DEV`, `STAGE`, `UAT`, `PROD` |
| `database_name` | `TEXT` | Database name |
| `ddl_type` | `TEXT` | `TABLES`, `PROCEDURES`, `FUNCTIONS` |
| `ddl_name` | `TEXT` | Object name (e.g. table name) |
| `ddl_content` | `TEXT` | The SQL DDL (`CREATE...`) |
| `file_path` | `TEXT` | Path to the local file |
| `exported_to_file` | `INT` | `0` (Pending), `1` (Synced) |

### Table: `comparisons`
Caches the results of database drift runs.

| Column | Type | Description |
|---|---|---|
| `src_env` | `TEXT` | Source environment name |
| `dest_env` | `TEXT` | Destination environment name |
| `ddl_name` | `TEXT` | Object name |
| `status` | `TEXT` | `new`, `updated`, `deprecated` |
| `alter_json` | `JSON` | Array of migration steps/SQL statements |
